Boot path ③: booting Linux from EDK II (UEFI).

  EDK II firmware (CODE + VARS in CFI flash) ──BDS──▶ UEFI Shell
      └─ runs startup.nsh from the ESP: `initrd` first, then the kernel's EFI stub

This path downloads **no third-party bootloader at all**. Debian's qemu-efi-riscv64 firmware
already carries:

  * the UEFI Shell (BDS falls back to it when there is nothing bootable);
  * the `initrd` command (OvmfPkg/LinuxInitrdDynamicShellCommand) - it registers a file from
    disk as the Linux initrd device path, which is what the kernel's EFI stub looks for;
  * so the kernel command line can simply be passed as arguments to the EFI application.

The ESP (EFI system partition) is a FAT16 disk holding three things: startup.nsh, Image (the
Alpine kernel, which has an EFI stub) and the initramfs. The disk is generated by this
project's own tools/mkfat.ts.

Distribution (--distro):
  alpine (default)  the kernel and the initramfs go onto the ESP we build; once BDS falls
                    through to the UEFI Shell, startup.nsh registers the initrd and starts
                    the kernel
  debian            the official generic cloud image as a whole disk. GPT: p1 = rootfs
                    (ext4), p15 = ESP (FAT16) carrying Debian's own GRUB. Hand that disk to
                    --disk and the firmware's BDS follows the removable-media rule straight
                    to \EFI\BOOT\BOOTRISCV64.EFI (measured: `Booting \`Debian GNU/Linux'` then
                    `Loading Linux 6.12.x+deb13-riscv64 ...`); GRUB then parses the kernel,
                    the initrd and root=PARTUUID out of the image. This path builds no ESP and
                    the script never reads ext4 on the host.
                    Download: ~312 MiB tar.xz (official cdimage) unpacking to a ~3 GiB .raw.
                    Reuse an image you already have instead of downloading again:
                      tools/bootstrap-edk2.sh --debian-image /path/to/debian13.raw
                    ⚠️ Slow and quiet: the whole chain is ~18.2B instructions / ~3.9 hours on
                    this emulator (README), and the image's own cmdline carries quiet, so
                    there is almost no output before login: - that is not a hang.
                    --timebase 100000000 in the boot command is required: at the default
                    10 MHz one virtual second is 10M instructions and systemd kills slow
                    tasks on virtual time.

Read this before changing the script:
  * This path needs OpenSBI too (the `fw_jump.bin` it fetches): the CLI requires either
    `--kernel` or `--bios`, and EDK II on RISC-V uses SBI for its timer, IPIs and reset -
    without an SBI firmware it never reaches the UEFI boot screen. The printed boot command
    therefore carries both.
  * Versions are always discovered at run time (EDK II from Debian's qemu-efi-riscv64
    package, Alpine from the official directory).
  * Everything lands in gitignored directories (firmware/, tmp/) and must never be
    committed: EDK II is a third-party binary while this project is Apache-2.0.
  * The two 32 MiB flash images are a hard EDK II requirement; the wrong size makes the
    firmware refuse them, so the script checks.

Usage:
  tools/bootstrap-edk2.sh                  # interactive: asks about the mirror if GitHub is unreachable
  tools/bootstrap-edk2.sh --mirror         # pre-authorise the mirror (unattended)
  tools/bootstrap-edk2.sh --no-mirror      # forbid the mirror
  tools/bootstrap-edk2.sh --no-esp         # firmware only; no ESP (and no kernel/initramfs)
  tools/bootstrap-edk2.sh --firmware-only  # the same thing, spelled more plainly
  tools/bootstrap-edk2.sh --alpine v3.24   # pin the Alpine branch (default latest-stable)
  tools/bootstrap-edk2.sh --distro debian  # switch to the Debian 13 whole-disk image (see above)
  tools/bootstrap-edk2.sh --debian-image D:/img/debian13.raw   # reuse an image already downloaded
  tools/bootstrap-edk2.sh --dir DIR        # use a different output directory (default tmp/boot)
  tools/bootstrap-edk2.sh --lang en        # English messages (default: follow the system locale)

  The PowerShell twin takes the same options with its own spelling: pwsh tools/bootstrap-edk2.ps1 -Help

The other two boot paths:
  tools/bootstrap-direct.sh      OpenSBI jumps straight into the kernel (shortest, fastest)
  tools/bootstrap-uboot.sh       OpenSBI → U-Boot → kernel (U-Boot fetches it from a FAT disk)
