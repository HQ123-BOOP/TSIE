Boot path ②: U-Boot fetches the kernel.

  OpenSBI fw_jump  ──▶  U-Boot (S-mode payload) ──fatload from a FAT disk──▶  kernel Image + initramfs

One real bootloader more than the direct path: U-Boot reads the kernel and the initramfs
off a virtio disk **as files** (fatload) and hands over with booti (the command line goes
through bootargs). That means two extra artifacts compared with ①: the U-Boot firmware, and
a FAT16 disk holding the kernel and the initramfs.

The disk is generated by this project's own tools/mkfat.ts - it does not borrow mtools or
mkfs.vfat, which do not exist on Windows anyway.

Distribution (--distro):
  alpine (default)  the kernel and the initramfs go onto a FAT16 disk we build, handed over
                    with booti
  debian            the official generic cloud image as a whole disk. GPT: p1 = rootfs
                    (ext4), p15 = ESP (FAT16) carrying Debian's own GRUB. The command script
                    uses `bootefi bootmgr` so U-Boot's EFI boot manager follows the
                    removable-media path to \EFI\BOOT\BOOTRISCV64.EFI; GRUB then parses the
                    kernel, the initrd and root=PARTUUID out of the image itself - so the
                    script never reads ext4 on the host and never needs to know the kernel
                    version. This path builds no FAT disk, only the command script.
                    Download: ~312 MiB tar.xz (official cdimage) unpacking to a ~3 GiB .raw.
                    Reuse an image you already have instead of downloading again:
                      tools/bootstrap-uboot.sh --debian-image /path/to/debian13.raw
                    ⚠️ Slow and quiet: the whole chain is ~18.2B instructions / ~3.9 hours on
                    this emulator (~1.3 MIPS, measured in the README), and the image's own
                    cmdline carries quiet, so there is almost no output before login: - do not
                    read that as a hang. --timebase 100000000 in the boot command is required:
                    at the default 10 MHz one virtual second is 10M instructions and systemd
                    kills slow tasks on virtual time.

Read this before changing the script:
  * Versions are always discovered at run time. U-Boot comes from Debian's u-boot-qemu
    package (the newest version in the pool directory). That package ships two ELFs; the one
    we want is qemu-riscv64_smode/uboot.elf (the build meant to be started by SBI firmware).
  * Everything lands in gitignored directories (firmware/, tmp/) and must never be
    committed: U-Boot is GPL-2.0 while this project is Apache-2.0.
  * Every download retries; when GitHub release assets are unreachable it asks before using
    a mirror.

Usage:
  tools/bootstrap-uboot.sh                 # interactive: asks about the mirror if GitHub is unreachable
  tools/bootstrap-uboot.sh --mirror        # pre-authorise the mirror (unattended)
  tools/bootstrap-uboot.sh --no-mirror     # forbid the mirror
  tools/bootstrap-uboot.sh --decompress    # pre-agree to unpacking the initramfs (unattended; boots 38.9% faster)
  tools/bootstrap-uboot.sh --no-decompress # do not unpack; keep only the .cpio.gz
  tools/bootstrap-uboot.sh --alpine v3.24  # pin the Alpine branch (default latest-stable)
  tools/bootstrap-uboot.sh --distro debian # switch to the Debian 13 whole-disk image (see above)
  tools/bootstrap-uboot.sh --debian-image D:/img/debian13.raw   # reuse an image already downloaded
  tools/bootstrap-uboot.sh --dir DIR       # use a different output directory (default tmp/boot)
  tools/bootstrap-uboot.sh --lang en       # English messages (default: follow the system locale)

  The PowerShell twin takes the same options with its own spelling: pwsh tools/bootstrap-uboot.ps1 -Help

Dependencies (what happens when one is missing):
  required  curl / tar / sha256sum  bundled with Git Bash
  required  node + tsx              packing the initramfs and generating the FAT disk both go
                                    through this project's own TypeScript tools
  optional  bsdtar / 7-Zip          to unpack U-Boot's .deb (an ar archive); an installed one
                                    is used as-is (Windows ships bsdtar as
                                    C:\Windows\System32\tar.exe). With neither present the
                                    script asks before borrowing a static bsdtar into a
                                    temporary directory, which it deletes afterwards.

The other two boot paths:
  tools/bootstrap-direct.sh      OpenSBI jumps straight into the kernel (shortest, fastest)
  tools/bootstrap-edk2.sh        EDK II (UEFI) firmware plus an ESP (boots Linux from UEFI)
