Fetch and assemble the TSIE boot artifacts in one go: OpenSBI firmware,
EDK II (UEFI) firmware, and an Alpine kernel plus initramfs.
This is the PowerShell twin of tools/bootstrap.sh, aimed at native Windows (pwsh).

Read this before changing the script:
  * Versions are always discovered at run time, never hard-coded. Alpine's
    packages move quickly and a pinned URL eventually 404s (the linux-lts-6.18.44
    URL this README once carried was already dead on 2026-09-26).
  * Everything lands in gitignored directories (firmware\, tmp\) and must never
    be committed: these are GPL-2.0 and other third-party artifacts, while this
    project is Apache-2.0.
  * Every download retries. This machine's network reaches dl-cdn and
    deb.debian.org only intermittently - the same host succeeds one minute and
    times out 21 seconds later - so retrying is not optional.
  * GitHub release assets cannot be fetched directly here (github.com answers,
    but objects.githubusercontent.com, which the 302 points at, times out), so a
    mirror is needed. A mirror is a proxy relay, so the script asks first
    (-Mirror pre-authorises it).
  * Downloads all go through curl.exe (the one Windows ships is enough), so this
    script and the .sh twin share one set of flag semantics (--retry / --noproxy
    / -4) instead of inheriting Invoke-WebRequest's differences.
  * cpio packing reuses the project's own tools/initramfs.ts (run through tsx):
    neither PowerShell nor Git Bash has a native cpio, and there is no reason to
    write a third implementation.

Usage:
  pwsh tools/bootstrap.ps1                      # interactive: asks about the mirror if GitHub is unreachable
  pwsh tools/bootstrap.ps1 -Help                # help; --help / -h / -? work too
  pwsh tools/bootstrap.ps1 -Mirror              # pre-authorise the mirror (unattended)
  pwsh tools/bootstrap.ps1 -NoMirror            # forbid the mirror; take OpenSBI from local files only
  pwsh tools/bootstrap.ps1 -NoEdk2              # skip EDK II (saves about 70 MB)
  pwsh tools/bootstrap.ps1 -Decompress          # pre-agree to unpacking the initramfs (unattended)
  pwsh tools/bootstrap.ps1 -NoDecompress        # do not unpack; keep only the .cpio.gz
  pwsh tools/bootstrap.ps1 -Alpine v3.24        # pin the Alpine branch (default latest-stable)
  pwsh tools/bootstrap.ps1 -Dir tmp/boot-pinned # use a different output directory (default tmp\boot)
  pwsh tools/bootstrap.ps1 -Lang en             # English messages (default: follow the system locale; TSIE_LANG works too)

  Pass -Dir with forward slashes or as a relative path: PowerShell treats \t and
  \n inside double quotes as escape sequences, so -Dir "G:\tmp\ps-test" silently
  becomes G:tmpps-test (\t is a tab).

EDK II needs a .deb unpacked (an ar archive): the bsdtar Windows ships is
preferred, with 7-Zip as the fallback. If neither exists the script warns and
skips EDK II (it never borrows a bsdtar from a third-party repository; only the
.sh twin has that path).

Notes:
  * Requires PowerShell 7+ (pwsh); Windows PowerShell 5.1 is not supported. On
    5.1 the script prints install instructions, waits 5 seconds and exits 1.
  * This script deliberately carries a UTF-8 BOM: 5.1 reads a BOM-less UTF-8
    script as ANSI/GBK and dies on syntax errors, which means it could not even
    read the install message above - the user would only see mojibake.
  * Known trap: dl-cdn redirects here and its speed swings between 45 KB/s and
    5 KB/s, so downloads use -C - to resume and decide completion from the final
    response's Content-Length. The .part file records its source URL, so changing
    source restarts the download.

Dependencies (what happens when one is missing):
  required  curl.exe              included in Windows 10 1803+, or install Git for Windows
  required  tar.exe               must be the bsdtar Windows ships, not Git's GNU tar.
                                  The two share a name but not their abilities: this
                                  script picks System32\tar.exe explicitly, because
                                  Git's tar.exe comes first on PATH and cannot read ar.
  required  node + tsx            tools/initramfs.ts packs the initramfs, and tsx is a
                                  devDependency (run npm install first). That step
                                  never touches the disk: it reads mode and linkname
                                  straight from the tar header, so neither "Windows
                                  cannot create symlinks" nor "Windows cannot store
                                  execute bits" affects it. Python is no longer needed.
  optional  7-Zip                 needed only for EDK II, and only as the fallback
                                  when bsdtar is unavailable. With neither present the
                                  script skips EDK II and warns.
  not needed xz                   OpenSBI ships as .tar.xz, but tar/bsdtar decompresses
                                  it through liblzma on its own.
